# WeeklyClaw.ai — Component Map & Update Contract

**Read this before ANY edit to this site.** Every content change touches several
connected surfaces. The most common agent failure is updating one place and
forgetting the rest (real example: W36 got a video player but no library page,
no timeline entry, no summary — because the video wiring and the catalogue are
separate systems).

If you change content, run the matching checklist below, then
`npm run build`, then push. Never hand-edit a generated file.

## The two data sources (know which one you are editing)

| Source | Type | Drives |
|---|---|---|
| `episodes.json` | hand-edited catalogue (canonical) | `/episodes/N/` detail pages, `/episodes` archive cards + summaries, `/timeline/` entries + search corpus, `public-episodes.json`, sitemap episode routes, homepage latest block (via build) |
| `/home/henrymascot/weeklyclaw/episodes/N/` (show-prep archive) | authored show content | copied in by `scripts/sync-weeklyclaw-archive.py` → `/episodes/N/deck.html`, `agenda/`, `host-cheat-sheet/`, YouTube/Spotify/audio player wiring on homepage + `/episodes`, thumbnails |

Everything below is **generated** — do not hand-edit:
`public-episodes.json`, `/episodes/N/index.html`, `/episodes/index.html`,
`/timeline/index.html`, `weeklyclaw-archive.html`, `sitemap.xml`, analytics tags
(re-added by `scripts/add-analytics.mjs`), and the needles inside
`scripts/validate.mjs` (the sync script rewrites them).

## Build pipeline (order matters)

```bash
npm run build     # = build:public-library → render:public-library → add-analytics → validate
npm test          # node --test scripts/*.test.mjs + public-library tests
```

- `scripts/build-public-library.mjs` — merges `episodes.json` + `data/public-episode-supplements.json` + `data/public-transcripts/eN.txt` into `public-episodes.json`. **Hash-gated:** every published transcript must match its manifest record (video ID, source URL, SHA-256) exactly or the build fails.
- `scripts/render-public-library.mjs` — renders all generated pages above from `public-episodes.json`.
- `scripts/add-analytics.mjs` — injects analytics into every public page. Sync rewrites pages without it, so **build must run after sync**.
- `scripts/validate.mjs` — asserts required assets + markup needles + changelog routes. `python3 scripts/sync-weeklyclaw-archive.py` updates its needles automatically.
- Deploy: push to `main` → Vercel builds. A failed deploy leaves the OLD site live — check the deployment, not the push.

## Transcript system (Fireflies-style, speaker avatars)

- Raw transcripts: `data/public-transcripts/eN.txt` — `[M:SS] text` cues, exported from YouTube captions. Header binds video ID + language.
- Manifest: `data/public-episode-supplements.json` — one record per published transcript: `status: "published"`, `sourceUrl`, `sourceHash` (SHA-256 of the txt), language, caption type, `speakerLabels`.
- Speaker attribution: E31 is the reference. Labels come from corroborated sources (e.g. Riverside transcripts), bound to exact cue text hashes — the build **fails closed** on mismatch. Never infer speakers from caption prose.
- UI: episode pages group cues by speaker; Henry and Andy get photo avatars
  (`assets/host-avatars/{henry,andy}.png` via `HOST_AVATARS` in the renderer);
  guests get initial badges. Timeline search covers all published transcripts.
- A catalogue row without a transcript must say `transcript.status: "missing"` — missing coverage is explicit, never silently omitted.

## Checklists by change type

### Publish a new episode (video live on YouTube)
1. Show-prep artifacts exist in the archive; `python3 scripts/sync-weeklyclaw-archive.py --commit --push` copies decks, wires players, downloads the thumbnail, updates validate needles.
2. Add the row to `episodes.json` (week, title, date, url, videoId, thumbnailUrl, summary bullets). **Without this the episode has no library page, no timeline entry, no summary** — the W36 gap.
3. Transcript: export captions → `data/public-transcripts/eN.txt` + manifest record with hash → status `published`. If unavailable, leave `missing` explicitly.
4. `npm run build && npm test`, push to `main`.
5. Verify live: `/episodes/`, `/episodes/N/`, `/timeline/`, homepage latest card, player wiring.

### Change hero portraits / site chrome
1. Edit `index.html` style blocks only; do not add generated backdrops (standing owner instruction: no new visual elements).
2. `node scripts/validate.mjs` — its needles reference current portrait assets.
3. Push; verify the exact asset URLs return 200 in production.

### Add a changelog deck (`/wNN/`)
1. Copy deck + slide JPGs into `/wNN/` (self-contained route) and link from `/changelog/`.
2. Update the changelog-route count in `scripts/validate.mjs`.
3. `sitemap.xml` is regenerated by build for episode routes only — add changelog routes to the source of truth the renderer uses if missing.

## Operations gotchas (learned 2026-10-31 / 11-01)

- **YouTube blocks this host's cloud IP** for yt-dlp/caption scraping. Owner-side caption pulls need the Data API (OAuth user token, service accounts do NOT work) or an authenticated browser session.
- The sync title parser accepts `Weekly Claw #N` and `Weekly Claw N` (`r"Weekly Claw\s*#?(\d+)\b"`). New title formats break episode detection — check the regex if episodes "disappear".
- `yt-dlp` must be installed via `uv tool install yt-dlp` on this host; pipx envs go stale.
- Sync runs as a scheduled job; concurrent hand-edits to `index.html` while sync/build are mid-flight cause failed builds. Commit content edits between sync runs.
- Vercel deploy failures keep serving the last good build — a green push is not a green deploy. Check the deployment.
